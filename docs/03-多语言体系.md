# 03 多语言体系(翻译表 + tt() 实时机翻闭环)

> 来源:YINJIA-MES(`C:\INCER\YINJIA-MES`)+ light-mes(`E:\INCER\light-mes` 为真源)。
> 一句话:**任意语言 = 翻译表加行不加列;前端 tt() 中文即键,渲染 miss → 自动机翻 → 落库 → 重渲**。
> 配套:00 C 类;术语见 YINJIA-MES `CONTEXT.md`(翻译分层/事实不翻/翻译表决策);红线 ADR-0001。

## 1. 术语与边界(先对齐再实现)

| 层 | 内容 | 存放 | 翻译方式 |
|---|---|---|---|
| UI 文案层 | 菜单/按钮/提示/布局文本 | 前端语言包(`*.js` 的 `biz` 平铺)+ 翻译表 | 静态包优先,miss 机翻兜底 |
| 面板标签层 | `yj_field.label` 字段标签、面板名 | 翻译表 `scope='field'/'panel'` | 后端按 Accept-Language 下发(别名>译名>中文) |
| 字典数据层 | 仓库/工序/类别等字典名 | 字典表译名列 | 随语言切换(字典翻) |

**事实不翻(红线)**:客户法定名、单号、用户输入备注、物料规格等业务事实**永不翻译**;机器译文不可控,保持原文是准确性要求。
**数据键不译(红线)**:`dataName`/`buttonName`/状态存储值/查询条件键永远是中文——只允许出现在显示层的翻译,提交后端的键原样中文。
**可接受机翻**:UI 零星文案;结果缓存回翻译表 `source='mt'`,管理员可人工校对升级为 `manual`。

## 2. 翻译表设计与语言注册表

**契约(两项目同构,表名 yj_* / sys_*)**:译文存行,不按语言加列。

```sql
-- YINJIA: yj_translation / yj_locale(tools\i18n-translation-table.sql)
--  scope: 'ui'(前端词条) | 'field'(字段标签) | 'panel'(面板名)
CREATE TABLE yj_translation (id int IDENTITY PK, scope varchar(20), ref_key nvarchar(200),
  locale varchar(10), text nvarchar(500), source varchar(10) DEFAULT 'manual',  -- manual=人工|mt=机翻缓存
  created_at, updated_at, CONSTRAINT uq UNIQUE (scope, ref_key, locale));
CREATE TABLE yj_locale (locale varchar(10) PK, name_zh nvarchar(50), name_native nvarchar(50),
  enabled bit DEFAULT 1, sort int DEFAULT 100);
-- light-mes: sys_translation(scope 默认 'biz',其余同构)/ sys_locale;见 db\init.sql
```

**ref_key = 中文原文**(字段 label/面板名/前端词条原文),同一中文标签全局共享译名。
**scope 域差异(契约对齐点)**:YINJIA 分 `ui`(前端词条)/`field`(字段标签)/`panel`(面板名)三域;light-mes 只有 `biz` 一词条域(面板名/字段标签交给前端 tt() 兜底)——移植时二选一,推荐三域(与后端配置生成器直连)。
⚠ **表注释陷阱**:`i18n-translation-table.sql` 里 yj_translation 的注释(旧口径 ref_key=`panel_code:col_name`)已过时——注释自述"后续 i18n-fix-refkey 统一重键为中文原文";**以代码与 AGENTS.md 为准(ref_key=中文原文)**。

**语言注册表**:`zh-CN` 恒在首位(不依赖表);其余 `enabled=1 ORDER BY sort;` 新增语言=INSERT 一行即扩展:
`INSERT INTO yj_locale VALUES ('ar',N'阿拉伯语',N'العربية',1,100);` 切换器自动出现,词条由机翻初始化、可人工校对。
种子集(YINJIA):en/ja/ko/es/fr/de/ru/vi/th/zh-TW;light-mes 同构。**静态内置语言**(YINJIA `BUILTIN`+`STATIC_PACKED` 11 语;其余语言完全动态)。

## 3. 前端 tt() 管线

**位置**:`frontend\src\i18n\index.js`(两项目同构)+ `stores\locale.js` + `main.js` 注册取词器。

**tt(text) 判定顺序**(YINJIA 版;light-mes 版有 `translatable()` 前置,语义一致):
1. 非字符串/空 → 原样;locale 为 zh-CN/zh → **直通原样**;
2. 组合标题(含 `' / '`,如「基础资料 / 客户档案」)按分隔符**逐段翻译回拼**;
3. `void dictVersion.value` 建立响应式依赖(渲染函数/computed 内的 tt() 词条补齐后**自动重渲**);
4. 读 `i18n.global.getLocaleMessage(locale)?.biz` 命中即返——**静态包优先,永不被机翻覆盖**(ensureDict 只提交缺失键,merge 不覆盖已有);
5. miss → `recordMiss(locale, text)` 记入 `pendingByLocale`(**requested 集合按 `locale+\u0000+key` 去重:机翻失败键本会话不再重试,防请求风暴**;键长>200 丢弃;未注册取词器则静默);
6. 去抖 **500ms** `flushPending()` → 已注册取词器(main.js:`registerDictFetcher((locale, keys) => localeStore.ensureDict(locale, keys))`)→ `POST /api/locale/dict {locale, keys}`(单批原子;light-mes 上限 50/批)→ `mergeLocaleMessage(locale, {biz: got})` → `dictVersion++` 界面重渲;
7. 任何失败:tt() 回退**中文原文**,不抛错不弹窗。

**词条静态包**:`i18n\locales\*.js`(命名空间 + `biz` 平铺、中文即键;`zh-CN.js` 无 biz 属正常——源语言直通);`en.js` 的 `biz` 全键导出为 `BIZ_KEYS`(供后端对新语言初始化机翻);`en.js` 注释要求**登录页词条必须收录**(无 JWT 取不到 /locale/dict)。YINJIA 另有 `SUPPORTED=['zh-CN','zh-TW','en']`(detectLocale 白名单)、`LOCALE_KEY='mes_locale'`、`DEFAULT_LOCALE='zh-CN'`、`STATIC_PACKED` 11 语(静态包语言切换即生效,不依赖机翻);light-mes `ensureDict` 会先过滤"当前 locale 缺失且长度≤200"的键再请求(静态包/已有机翻结果不会被覆盖),`DICT_BATCH_LIMIT=50` 分批。

**语言状态(uses locale store)**:`set(locale)` 热切换——不刷新页面、不重置任何数据/分页/弹窗/滚动:写 localStorage(`mes_locale`)→ `apply()`,`i18n.global.locale.value` + `document.documentElement.lang` + 标题;可选语言 `loadAvailable()` 取 `/api/locale/list`(失败回退内置两语);`cycle()` = **Alt+L** 循环;`EP_LOCALES` 映射 Element Plus 组件文案(zh-CN/zh-TW/en/ja/ko/de/fr/es/ru/th,缺失回退 en/zhCn),经 `App.vue` `<el-config-provider :locale="epLocale">` 即时生效;请求头 `core\request.js` 注入 `Accept-Language`(见 §4)。

## 4. 后端(Accept-Language 驱动 + 30s 缓存 + 机翻)

**入口**:`LocaleController`(YINJIA `controller\LocaleController.java`;light-mes `com\mes\controller\LocaleController.java`,`@RequestMapping("/api/locale")`):
- `GET /list` → 语言列表(zh-CN 恒首 + 注册表行;失败仅中文);
- `POST /dict {locale, keys:[中文原文]}` → **契约差异**:YINJIA 返回 `{locale, dict:{中文→译名}}`(前端取 `data.dict` merge);light-mes 直接返回裸 `Map{中文→译名}`(前端 localeDict 直接 merge)。**zh/zh-CN/空/keys 空 → 空 dict 直通**;keys 去空白、超上限截断(light-mes `max-keys-per-request` 默认 50,超出告警)。

**Accept-Language 驱动面板配置**(YINJIA 独有,light-mes 以前端 tt 兜底为主):
`core\request.js` 把当前 locale 注入 `Accept-Language`(`en,en;q=0.9,zh;q=0.5`;zh-CN 也发)→ Spring `LocaleContextHolder` → `PanelConfigService.localeKey()`(=`TranslationService.localeKey`:en-US→en,zh-TW/HK/MO→zh-TW,zh 系→zh)→ 生成配置时 `translations.scope(locale,'field'/'panel')` 选出 `displayName/columnAliases/panelName/页签名`(规则:别名 > 译名 > 中文);轻量常量如 明细/列表/汇总 直接 `translations.translate(locale, [...])` 一批取回。`dataName/buttonName` 永不随 locale 变化。

**翻译表查询 + 30s per-locale 缓存**:
- YINJIA `TranslationService`:缓存结构 `locale → scope → (中文→译名)`,`loadedAtByLocale` 记录各语言加载时间;`byLocale(locale)` TTL 30s(`TTL_MS=30_000`);`invalidate` 只删对应语言键——避免他语 reload 掩护本语过期数据;`translate()` 先查 ui scope 再 field scope,miss 项并行机翻,完成后统一落库再失效缓存。
- light-mes `TranslationService`:`CacheEntry(dict, expiresAt)` per-locale(`mes.mt.cache-ttl-seconds` 默认 30);`dict()` 三级=缓存 → `sys_translation(scope='biz')` → 机翻;每次只 merge 本次 wanted 键。

**机器翻译(与 OCR 同凭据)**:
- YINJIA 配置键 **`yinjia.ocr.access-key-id/access-key-secret/endpoint`**——与 OCR 服务**同一组 AK/SK**;`mtClient()` 由 OCR endpoint 推断 `mt.<region>.aliyuncs.com`(`regionOf` 取 cn-/ap-/us-/eu- 段,缺省 cn-hangzhou);线程池 **10 并发**(daemon `mt-translate`);请求 `TranslateGeneralRequest(scene=general, source=zh, target=aliLang(locale), format=text)`;**zh/zh-CN 直通**(`translate()` 直接返回空 map),**zh-TW 放行**(`aliLang`:"zh-TW"→"zh-tw",其余 ISO-639-1 原样)。
- light-mes 配置键 `mes.mt.access-key-id/secret/endpoint`(默认 `mt.cn-hangzhou.aliyuncs.com`)+ connect/read 超时;线程池 8;`localeKey()` 归一相同口径(zh/zh-CN→""直通,zh-TW/HK/MO→"zh-TW" 放行);机翻失败/无凭证/超时 → 返回空 → 前端回退中文,**绝不抛出**。
- **写回**:YINJIA `MERGE yj_translation ... WHEN MATCHED UPDATE ... WHEN NOT MATCHED INSERT (source='mt')`——**派生表参数必须显式 `CAST(... AS nvarchar)`,否则非拉丁文字(泰文/俄文等)被驱动按 varchar 发送替换成 `??`**(历史踩坑);light-mes `INSERT ... ON DUPLICATE KEY UPDATE text/source`(批内逐条,失败仅告警)。库表写失败不影响本次返回。

## 5. 复现步骤(给 agent)

1. **建表**:`*_translation`(scope/ref_key/locale/text/source,UNIQUE(scope,ref_key,locale))+ `*_locale` 注册表;插入常用语言种子(zh-CN 逻辑恒首,不入表);
2. **后端**:实现 `TranslationService`(三级:内存 TTL 30s → 翻译表 → 机翻写回)+ `LocaleController`(/list、/dict);面板配置生成器接入 `scope(locale,'field'/'panel')`(显示名下发),数据键不动;
3. **前端**:vue-i18n 建 `messages`(zh-CN 空包 + 静态包);实现 `tt()`/`recordMiss`/`flushPending`/`dictVersion`(按 §3 管线)+ locale store(`apply/ensureDict/cycle/EP_LOCALES`)+ `main.js registerDictFetcher` + `request.js` 注入 Accept-Language + `App.vue el-config-provider`;
4. **全界面显示点用 `{{ tt('中文原文') }}` 包裹**(含占位符/tooltip/标题);新增面板/字段按 AGENTS.md 规范同步插 `yj_translation` 行(scope='panel'/'field',至少 en,鼓励全语言);
5. **新语言** = `INSERT *_locale` 一行 + 前端 `EP_LOCALES` 一行(无 EP 包回退 en)——其余零代码。

## 6. 验收锚点

- 切换到 en/ja/任意注册语言:**新增面板、字段、按钮词条自动机翻出现译文**,无需预置翻译;刷新后命中翻译表(source='mt')不再触发机翻;
- 切回 zh-CN 全部原文;zh-TW 独立译名/机翻(放行口径);数据键与提交给后端的键恒中文;
- 断网或无凭证:全界面回退中文,无报错、无请求风暴(失败键会话内不重试);
- 顶栏下拉 + Alt+L 循环切换,Element Plus 组件文案同步,页面状态不重置;
- 后端 `/api/locale/dict` 对 zh-CN 返回空 dict;`en` 返回的键与请求 keys 一一对应(失败键缺席)。

## 7. 常见坑(移植前必读)

1. **`??` 污染**:SQL Server 写回未 CAST nvarchar → 泰文/俄文等被替换成问号(轻则词条丢失,重则中文变 `??`);库表如有存量污染用 light-mes `tools\repair-db-question-marks.cjs` 修复;
2. **tt() 只用于显示层**:v-model、选项 value、query payload、callButton 的 buttonName、`=== '已审核'` 匹配一旦经过 tt() 即产生"数据键被翻译"bug(最隐蔽的红线破坏方式);
3. **组合标题仅识别 `' / '`**(两侧空格):`'基础资料/客户档案'` 不分段,保持同一分隔符;
4. **键长上限 200/500**:超长键被静默丢弃(前端)或截断(后端),提示文案要短;
5. **静态包必须覆盖登录页**:登录场景无 JWT,取不到 `/locale/dict` 机翻;
6. **zh-TW 无静态包时依赖机翻**(`aliLang` 映射 zh-tw);`zh-CN` 恒直通,不要给 zh 系语言配空走翻译管线;
7. **merge 只增不删**:`mergeLocaleMessage` 不会移除旧键,语言包改词条后旧译名可能残留——以"静态包优先+缺失才请求"策略保证不被覆盖,但删词条需手动清理。
