# 08 工程与部署（迁移清单 / 一键构建 / 回归审计 / 单 jar）

> 来源：YINJIA-MES（C:\INCER\YINJIA-MES）为主实现，light-mes（E:\INCER\light-mes）为参照。
> 环境基线：YINJIA = Spring Boot 3.5.3（Spring Boot 3 + JDK 17+）+ SQL Server HSDZ_MES（1433），后端 8090，前端 Vite 6 dev 5173 / preview 4173；
> light-mes = MySQL（默认 localhost:3308）+ 后端 8080。
> 标注沿用 00 盘点：**[共]** · **[L]** light-mes 独有 · **[Y]** YINJIA 独有。

## 0. 设计意图

生产 MES 的工程链要解决四件事：库结构随代码演进可回放（他人改库不冲突）、任意机器一键可跑（工具链入仓不依赖个人环境）、数百面板上线前可回归（API + DB 静态双校验）、部署出一条可运行产物（单 jar / 差集脚本）。本文给出对应四件套。

## 1. 数据库迁移清单 + 增量同步工具

### 要点

- **唯一权威清单** `tools/db-migrations.txt`（49 项，按行序执行）；新增脚本插入合适位置：表结构 → 元数据 → 数据 → 翻译 → 视图 → 修复类放最后。
- `DbSync.java` [Y]（`tools/`）：按清单对每个脚本计算 **SHA-256**，与日志表 `yj_schema_log`（`script_name` 主键 / `content_hash char(64)` / `applied_at`）比对——未记录或哈希变化才执行，否则跳过；失败即中止后续脚本。
- 三种模式：`sync`（默认增量）/ `baseline`（仅把清单脚本标记为已执行，不动数据）/ `run <脚本名>`（无视记录强制重跑并记录）。
- SQL Server 警告白名单 `INFO_CODES = {0, 5701, 5703, 5704, 15477}`（PRINT/库上下文/语言/sp_rename 提示）；白名单外非 0 码视为语句错误——**建视图失败必须报错**，防止静默漏建对象。
- 脚本按 `GO` 批自动提交（与 sqlcmd 一致的 `splitGo`），中途失败可能部分生效且**不写记录**→ 修复后重跑即可收敛；因此脚本必须幂等（清单头注释硬规则：`IF NOT EXISTS` / `DELETE+INSERT` / 游标补列），**内容变化会触发重跑**。
- `DbInit.java` [Y]：全量初始化（SQL Server 单用户模式 + NTLM 以管理员连接 → RESTORE 备份 → 创建 `yinjia` 登录 → 按**同一清单**顺序执行并记录）；`BASE` 目前硬编码 `D:\YINJIA-main\YINJIA-main\tools\`，复现须改为项目路径。
- `pull-sync.bat`：`git pull` → `DbSync`（JDBC 驱动 `tools\lib\mssql-jdbc.jar`，缺则 `.m2-repo\com\microsoft\sqlserver\mssql-jdbc\12.8.1.jre11\...`）。
- [L] light-mes 无 DbSync：基线 `backend/src/main/resources/db/init.sql` + 增量 `tools/update-*.sql` 手工批，`repair-db-question-marks.cjs` 检查中文 `?` 编码污染。

### 关键脚本路径

- `YINJIA-MES\tools\db-migrations.txt`、`DbSync.java`、`DbInit.java`、`pull-sync.bat`、`enable-mixed-auth.ps1`
- `YINJIA-MES\tools\setup-db.sql`（幂等种子：`yj_*` 元数据表 + 登录账号）
- `E:\INCER\light-mes\tools\repair-db-question-marks.cjs`、`build-deploy-sql.mjs`

### 复现要点

1. 迁移清单即真相：任何 DDL 改动先挂清单，禁止在库上手工直改，否则 DbSync 无法追踪（他人库永远落后）。
2. 日志表由工具 `ensureLogTable` 自动创建；存量库先 `baseline` 标记存量脚本，全新库直接 `sync`。
3. 失败重跑语义 = 幂等收敛：部分生效不写记录 → 修脚本 → 重跑；控制台按 `[新增]/[变更]/[跳过]` 三态核对。

## 2. 一键启动 / 构建（JDK 探测 / Maven 固定版）

### 要点

- **JDK 探测**（全部 bat 一致）：`JAVA_HOME` → 常见安装目录（`C:\Program Files\Java\jdk-26.0.2`、`D:\Program Files\Java\jdk-26.0.2`、`jdk-24`、`jdk-17`）→ PATH `java`；要求 17+。
- **Maven 固定版**：`tools\apache-maven-3.9.9` + `tools\settings.xml`（镜像/仓库配置）入仓，`MAVEN_HOME` 不依赖系统安装；构建带 `-DskipTests`。
- `backend\build.bat`：JDK 探测 → 固定 Maven `package` → `target\yinjia-mes-backend-0.1.0.jar`。
- `start-project.bat`：探测 JDK → 校验 jar 存在（否则提示先 `build.bat`）→ 读 `backend\.env` 注入阿里云密钥 → 起后端 8090 → `npm run dev` 前端 5173。
- `tools\start-backend.bat`：只起后端；AK/SK 从进程/用户级环境变量读取，以 `--yinjia.ocr.access-key-id/secret` 参数注入（OCR 与机翻同凭据）；文件注释保持 ASCII（cmd 会误解析 UTF-8 中文注释）。
- [L] light-mes：`tools\detect-jdk.bat`（统一探测）+ `backend\build.bat`（`clean package -DskipTests` → `target\light-mes-backend-0.1.0.jar`）+ `backend\run.bat` + `start-project.bat`（4173 preview）；端口环境变量化（`MES_HTTP_PORT` / `MES_DB_HOST/PORT` / `SPRING_DATASOURCE_PASSWORD` / `MES_JWT_SECRET`），换机器只设环境变量不改文件。

### 关键脚本路径

- `YINJIA-MES\start-project.bat`、`backend\build.bat`、`tools\start-backend.bat`、`tools\apache-maven-3.9.9`、`tools\settings.xml`
- `E:\INCER\light-mes\tools\detect-jdk.bat`、`backend\build.bat`、`backend\run.bat`、`start-project.bat`

### 复现要点

1. 工具链入仓（固定 Maven + `settings.xml` + JDBC 驱动 jar），机器只留 JDK，消灭「我机器能跑」差异。
2. 密钥不进仓库：`backend\.env`（本地，`build.bat`/`start-project.bat` 读取）或环境变量；缺失时 OCR/机翻自动降级（接口明确报「服务未配置」）。
3. bat 全部 `chcp 65001` 处理中文输出；`start-backend.bat` 的注释必须 ASCII。

## 3. 全量面板回归审计（API + DB 静态校验）

### 要点

- `audit-panels.ps1`（本地 8090）：admin 登录 → 从 `yj_panel` 拉全量 `panel_code` → 逐个调 `GET /api/px/getPanelConfig`（**配置生成**）与 `POST /api/px/queryFormDataList`（**数据查询冒烟**，pageSize=1），`code != 200` 记 FAIL，输出 ok/fail 统计。
- 同脚本内 DB 静态校验（临时 `_audit-db.sql`）：`MISSING_TABLE` = `yj_panel.line_table/head_table` 的 `OBJECT_ID(...) IS NULL`（**表/视图缺失**，OBJECT_ID 不分对象类型）；`MISSING_COL` = 真实表（U）上 `yj_field.col_name` 不在 `sys.columns`（字段引用漂移）。
- `_audit-db2.sql`（**字段列按 header/detail 分表比对**）：`place LIKE '%header%'` 字段对 `head_table`、`place LIKE '%detail%'` 字段对 `line_table`，逐一与 `sys.columns` 比对——比单一 line 表检查更严，覆盖表头列。
- `audit-conditions.ps1`（**condition 查询冒烟**）：8 个代表面板（SO_ORDER / PU_ORDER / MANU_ORDER / DEPT / KHDA / RD_FILTER_EFF / DISPATCH / INV）用「不存在值」condition 查询，专抓中文键→SQL 分支映射错误。
- `audit-remote.ps1`：同一套 API 冒烟打远程生产（36.140.66.163:8090），面板清单从远程库经 sqlcmd 拉取。
- 依赖：运行中服务 + 登录账号（admin/123456，可改）+ `sqlcmd`（本地 `-E` 或远程 `-U/-P`）+ `curl.exe`；结果写 `tools\_audit-*.txt`。

### 关键脚本路径

- `YINJIA-MES\tools\audit-panels.ps1`（内嵌 `_audit-db.sql`）、`_audit-db2.sql`、`audit-conditions.ps1`、`audit-remote.ps1`
- 配套：`tools\verify-api.ps1`（登录/面板配置/读写/审核/作废/档案保存/库存状况/通知/OCR 路径）

### 复现要点

1. 「API 冒烟 + DB 静态校验」互补：API 侧抓运行时错误（配置生成/查询/权限），DB 侧抓元数据与库结构漂移（表/视图/列三查）。
2. 把审计当作上线 gate：`CFG-FAIL`/`QRY-FAIL` 为 0、DB 静态校验 0 条问题、condition 冒烟无 FAIL 才可发布。
3. 条件冒烟选**有代表性的面板**（单据/档案/报表/单单据）+ 不可能命中的值，噪音最低、命中率最高。

## 4. 单 jar 一体化部署 + 差异部署工具

### 要点

- **单 jar** [Y]：前端 `npm run build` 产物（`index.html` + `assets/*`）放入 `backend/src/main/resources/static`（已随仓库），`spring-boot-maven-plugin` 打成单个 `yinjia-mes-backend-0.1.0.jar`，前后端同源。
- **Security 放行**（`config/SecurityConfig.java`）：`OPTIONS /api/**`、`/`、`/index.html`、`/favicon.ico`、`/assets/**`、`/vite.svg`，及 `/api/auth/login`、`/api/base/factory/list`、`/api/locale/list`、`/api/locale/dict` 匿名；其余 `/api/**` 全部认证。前端为 **hash 路由**，故无需服务端 history fallback。
- 运行：`java -jar target\yinjia-mes-backend-0.1.0.jar`（8090）；`application.yml` 支持环境变量注入（`YINJIA_JWT_SECRET`、`ALIBABA_CLOUD_ACCESS_KEY_ID/SECRET`）。
- **差异部署 `_DeployGen.java`**：对比本地与远程（36.140.66.163）的 `sys.tables/sys.views` 差集 → 生成 `tools\deploy-all.sql`（`CREATE TABLE`（列元数据/IDENTITY/DEFAULT）+ 数据 `INSERT`（200 行/批、`IDENTITY_INSERT ON/OFF`）+ 对缺失视图 `CREATE OR ALTER VIEW`（取 `sys.sql_modules.definition`））；排除 `t1/t2/dtproperties`。
- **`_DeployExec.java`**：按 `GO` 批执行 SQL 文件，逐批捕获异常并输出 `batch# + 错误头`（继续后续批），汇总 `executed/failed`。
- 注意：`_DeployGen/_DeployExec` 内写死本地/远程连接串与账号密码（含 `sa` 口令），**复现必须参数化/环境变量化**；`deploy-all.sql` 只补「缺的对象」，不迁移约束/索引/权限。

### 关键脚本路径

- `YINJIA-MES\backend\src\main\resources\static\`（前端内嵌产物）+ `config\SecurityConfig.java` + `application.yml`
- `YINJIA-MES\tools\_DeployGen.java`（输出 `tools\deploy-all.sql`）、`tools\_DeployExec.java`

### 复现要点

1. 单 jar 三前提缺一不可：dist 进 `static`、Security 放行静态路径、hash 路由——否则 404 或重定向循环。
2. jar 是唯一部署单元：目标机只需 JDK + jar + 环境变量（数据源/密钥），无需 Node 与前端目录。
3. 日常演化走 migrate：`migrate-*.sql` 挂清单交给 `DbSync`（幂等+哈希）；`_DeployGen/_DeployExec` 只用于**历史库差集**的一次性对账，不要当常规迁移手段。

## 5. 验收锚点

- 全新库：`DbInit.java`（或 `setup-db.sql` + `DbSync`）执行完，面板总数与 `yj_panel` 一致，无 `[缺失]/[SQL FAIL]`。
- 修改任一枚迁移脚本内容（如补一行注释）→ `DbSync` 显示 `[变更]` 并重跑；改回 → `[跳过]`。
- `audit-panels.ps1`：CFG-FAIL / QRY-FAIL 为 0，DB 静态校验 0 条；`audit-conditions.ps1` 无 FAIL。
- 只拷 jar 到无 Node/无 Maven 的机器，`java -jar` 启动后访问 `http://localhost:8090/` 直接出现登录页且可完成登录。
