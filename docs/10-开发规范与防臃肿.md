# 10 开发规范与防臃肿(项目通用版)

> 任何项目在功能持续增长时,按本规范开发可**避免**「代码堆叠、复制粘贴、大文件、改一处坏三处、
> 新旧两套并存」的屎山化。原则:**能靠工具自动守住的,不靠自觉**;新代码红线优先,存量问题进技术债清单逐步清理。
> 配套:系统通用设计资产库(01-09)提供「先查再用」的复用底座;Git 单任务单提交保证可回滚。

## A. 分层与边界(强制)

1. **通用层与业务层分离**:引擎/框架级代码(UI 控件、契约运行时、公共弹窗)禁止反向依赖业务代码
   (界面/领域/页面)。用架构审计脚本自动检测(如 core 层不得 import business 层)。
2. **后端三层纪律**:Controller 只做参数校验与转发;业务在 Service;持久化在数据访问层;
   禁止 Controller 写 SQL、写业务规则。
3. **单向依赖**:领域动作通过「扩展点/处理器注册表」注入,通用层不感知具体业务。
4. **响应契约统一**:统一 `{code,message,data}` 信封与异常归一化(4xx/5xx 映射),禁止各造格式。

## B. 契约与数据驱动(防"需求变 → 代码变")

5. **数据驱动优先**:字段/面板/选项等**配置化**——加字段=加配置行,而非改代码;
   若"加一个新字段要改前后端代码",说明违反数据驱动,应重构回配置。
6. **契约冻结**:对外接口/运行时契约变更 = 重大变更:更新文档、给兼容期、留迁移说明。
7. **数据键红线**:展示层翻译、存储层用稳定键;禁止把「用作文本展示的键」和「业务事实键」混用或改写
   (YINJIA 的 ADR-0001 即此类红线)。

## C. 文件与代码组织(防大文件)

8. **文件红线**:Vue 组件 ≥ 1200 行、JS/TS 模块 ≥ 800 行、Service/Controller ≥ 800 行必须拆分
   (子组件/组合式函数/领域服务);新代码超线=未完成。
9. **单一职责**:一个服务/一个组件只管一件事;通用能力下沉(公共弹窗、工具函数、composable);
   禁止"上帝组件/上帝服务"。
10. **命名一致**:文件名=组件名/类名=职责;数据键字段名与列名一一对应。

## D. 反复制粘贴(屎山最大来源)

11. **三次法则**:同一逻辑出现 3 处 → 必须抽取公共实现;先查已有仓库/资产库再动手。
12. **禁止平行实现**:系统级能力(表格列自定义、参照选择、导入导出、状态机、权限、翻译、占用/生单…)
    只允许一套实现;新需求优先增强现有实现。
13. **状态/权限判断收敛**:状态判据、权限判据用共享工具/常量,禁止各处散落硬编码。

## E. 可维护性与清理

14. **删除=彻底**:删除功能必须连同代码/表/菜单/词条一并清理,或显式标注 `@Deprecated` + 处置脚本。
15. **库变更留脚本**:禁止手工改库;迁移脚本必须幂等、进清单、执行验证。
16. **技术债台账**:存量问题记入清单(大文件/重复代码/历史硬编码),每完成一个版本清理一批;新代码不新增债。

## F. 自动化防线(提交前必须全绿)

17. 构建(`build` / `npm run build`)通过;
18. 架构审计(core 边界)/ 文档审计 / 全量接口回归脚本通过;
19. 敏感信息扫描(密钥/口令不入库);
20. lint(如启用)、单测(如有)通过;
21. 涉新资源的走查验收(如切换语言无中文残留)。

## G. 演进守则

22. 新功能先查**通用设计资产库**(本库 01-09)→ 有则复用/增强,无则新增**并回写资产库**;
23. 每完成一批功能做一次「重复/大文件/死代码」扫描(对照 C/D/E),结果记入技术债清单;
24. 每次任务修改独立 git commit(单任务单提交),保证任意时间点可回滚。

---

## 检查清单(每次任务收尾 30 秒)

- [ ] 没违反分层边界 / 没在 Controller 写业务
- [ ] 新字段/面板走配置,没改引擎代码
- [ ] 查过已有实现/资产库,没有平行造轮子
- [ ] 无 3 处复制(已抽取公共)
- [ ] 文件没超红线,新文件职责单一
- [ ] 删除的功能已彻底清理(或标注废弃)
- [ ] 库改动有幂等脚本并已验证
- [ ] 独立 commit,消息合规
- [ ] build/审计/走查全绿
