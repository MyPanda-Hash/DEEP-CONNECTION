# 01 面板引擎与数据契约(面板驱动基座)

> 来源:YINJIA-MES(`C:\INCER\YINJIA-MES`)+ light-mes(`E:\INCER\light-mes` 为真源)。
> 本文给 agent 的结论:**面板/字段全部由元数据表驱动,前端零硬编码;新增面板 = 元数据插行。**
> 配套:`docs/00-系统通用设计盘点.md` A 类;表 DDL 见各项目 `tools/`。

## 1. 设计意图

把「面板是什么样」从代码搬进数据库/注册表,让唯一的运行时契约驱动全部 UI:
- 前端 `PanelxList.vue`/`PanelxForm.vue` 只认 `getPanelConfig` 返回的 JSON(metadata/panelPageDto/dataSchema/detail),
  不写任何面板专属 if/else;后端按元数据生成该 JSON。
- 后端只实现**通用生命周期**(查询/保存/删除/审批),**领域动作**(生单/占用/校验)走按钮注册表扩展点。
- 因此:加面板=插行;改字段=改行;两项目实现各一(见 §3),可互相印证。

## 2. 契约

### 2.1 元数据表(两套,同语义)

| 项目 | 表/载体 | 关键列 |
|---|---|---|
| YINJIA | `yj_panel` + `yj_field`(HSDZ_MES,见 `tools/setup-db.sql`) | yj_panel:panel_code/panel_name/category/mode(doc\|archive\|flat)/line_table/head_table/group_col/pk_col/code_col/prefix/date_col/page_size/detail_key/module_group;yj_field:col_name/**label(中文=数据键)**/data_type/dict_sql/ref_panel/ref_field/display_field/place(query\|header\|detail)/seq/width/editable/required/hidden/alias/visible |
| light-mes | `panel_config`(config JSON 一列)+ 4 个代码 Registry 启动同步 | panel_code/panel_name/category/module_group/config(metadata+dataSchema+detail)/version |

### 2.2 px 运行时接口(`/api/px`,统一信封 `ApiResult{code,message,data}`,成功 code=200)

| 接口 | 方法/参数 | 返回 data |
|---|---|---|
| `getPanelConfig` | GET `?panelCode` | 面板配置(§2.3),light-mes 额外按登录用户叠加列定制 |
| `getPermMatrix` | GET `?panelCode` | `{privilege:{actionPrivileges:[{name,visible,operatable}],fieldPrivileges,groupPrivileges}}`(light-mes 按用户权限过滤) |
| `getNewFormPermMatrix` | GET `?panelCode&operationName` | 新增态权限矩阵 |
| `getFormDescriptor` | GET `?panelCode&code` | `{data:表头行, detailData:{key:[]}}`(单张单据全量) |
| `queryFormDataList` | POST `{panelCode,keyword,condition,pageNo,pageSize}` | `{rows,total}`(列表行;报表=行集合) |
| `getApprovalHistory` | GET `?panelCode&code` | 审批历史行 |
| `callButton` | POST `{panelCode,buttonName,formData,buttonParam}` | 动作结果(新单号/提示等);无名注册动作走通用生命周期 |
| `deleteForms` | POST `{panelCode,rowCodes[]}` | 批量删除(审核/草稿分开处理) |

前端适配器扩展辅助(面板引擎附带):`queryRefRows/refRowCount/refSelectOptions/refColumns/refPanelName/refLabelOf/fieldOptions`(参照+字典)、`recognizeFormImage`(OCR)、`fillCurrentStock`、`roundDecimal`、`errMsg`——即 `core/panel-runtime.js` 的 `REQUIRED_METHODS` 全集。

### 2.4 面板模式(模式决定生成器:doc/archive/flat)

| 模式 | 用途 | 结构要点(生成器) |
|---|---|---|
| `doc` | 头+明细单据 | dataSchema=表头字段;detail.tabs[items]=明细+calc+summaryItems;gridTabs=明细\|汇总(summary=true);可带 selectConfig;工具栏按 PANDA 复刻+生单/选单占位固化位 |
| `archive` | 单单据(基础档案)全字段一页签 | singleDoc=true;dataSchema 仅"备注";全部业务字段在 detail.tabs 单页签;gridTabs.rowSource=rows;panelState=状态(启用/已作废) |
| `flat` | 报表行 | 全部字段直接为网格列;工具栏=查询/打印/更多;前端按 metadata.report 或 category='报表' 进入报表模式 |

### 2.5 中文数据键约定(ADR-0001,红线)

`dataName`/`buttonName`/状态存储值(`已审核`/`草稿`)/条件键(**永不翻译**;v-model、选项 value、查询 payload、callButton 的 buttonName、`=== '已审核'` 匹配一律不经 tt)。翻译只发生在**显示层**:后端按 Accept-Language 下发 `displayName/columnAliases/panelName`(别名>译名>中文),前端 `tt()` 直译标签。

## 4. 复现步骤(给 agent)

1. **建元数据表**:照 `YINJIA tools\setup-db.sql` 建 yj_panel/yj_field(或照 `light-mes db\init.sql` 建 panel_config)并插入种子面板;
2. **注册面板/字段**:YINJIA=直接插行(PanelRegistry 30s TTL 自动生效);light-mes=写 PanelDefinition 于对应 Registry(启动 upsert 覆盖 config)或 SQL 维护 config JSON;
3. **实现运行时服务**:按 §2.2 接口实现 PanelRuntimeService(查询用 line_table/head_table 直映 SQL;light-mes 读 form_data JSON);callButton 内为领域动作注册 PanelActionHandler;
4. **前端安装**:main.js `installPanelRuntime(业务适配器)`(必须实现全部 REQUIRED_METHODS);路由挂 PanelxList(页面+`?code=` 单据参数);
5. **加面板=插行**:不再有第 5 步——重复 1-2 即可,前端零改动。

## 5. 验收锚点

- 元数据插入一个新 doc 面板后:**不改任何前后端代码**,门户/菜单出现该面板,列表、查询区、明细节格、工具栏按钮组(灰态占位)完整;
- 修改 yj_field 某字段 label/宽度/显隐/alias/required,30s 内面板自动生效(YINJIA 缓存 TTL);
- callButton 对一个只注册了「保存」的面板发「生成XX」,前端按钮恒置灰、点击无动作不报错。
