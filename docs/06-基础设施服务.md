# 06 基础设施服务:OCR 扫描填单 / 机翻 / 通知 / 报表 / 导入导出

> 能力地图 **F(基础设施服务)**。双实现互证:
> **YINJIA-MES**(`C:\INCER\YINJIA-MES`,JdbcTemplate + 物理表) × **light-mes**
> (`E:\INCER\light-mes`,MyBatis-Plus)。OCR 与机翻模块 YINJIA 均为「移植自 light-mes」,
> 类名/结构逐一对等,本文以 YINJIA 路径为主、light-mes 差异注解。

## 0. 设计意图

这些服务与业务面板正交:换任何 MES 都长一个样。总原则:**云厂商只做识别/翻译,校验、字段映射、
限流、落库全在服务层**(可测试、可换厂商、可离线降级);**配置驱动**(面板元数据即映射表,零注册);
**拿不到结果时要静默降级回退原文/原图**,绝不阻塞主流程。

## 1. OCR 扫描填单

### 契约

- 接口:`POST /api/ocr/scan-form`(multipart:`image` + `panelCode`)→
  `ApiResult<OcrScanResponse{requestId, header{中文标签:值}, detail{tabKey:[行]}, matches[], warnings[]}>`。
  前端 `core/views/ScanFillDialog.vue` 接收后回填表单(matches 逐字段给出「哪个字段→识别值」
  供人工核对,识别为空/无表时靠 warnings 提示)。
- **网关抽象 `OcrGateway`**(`ocr/OcrGateway.java`):唯一边界 `recognize(InputStream) → OcrDocument(
  requestId, rawText, lines[OcrLine(text, confidence)], tables[OcrTable(cells[OcrCell(
  rowStart,rowEnd,columnStart,columnEnd,text)])])`;失败抛受检 `OcrGatewayException`。
  校验与结构映射**不在网关内**(换厂商只换实现类)。
- 异常归一(见 05 文):`OcrGatewayException` → `OcrServiceException`(503)、限流 → `OcrRateLimitException`(429),
  均走 body-code,不触发前端登出。

### 关键文件路径

| 件 | YINJIA | light-mes |
|---|---|---|
| 网关接口 | `backend/.../mes/ocr/OcrGateway.java` | 同(com.mes.ocr) |
| 阿里云实现 | `ocr/AliyunOcrGateway.java` | `com.mes.ocr.AliyunOcrGateway` |
| 扫描编排 | `service/OcrScanService.java` | `service/OcrScanService` |
| 字段映射 | `service/OcrFormMapper.java` | `service/OcrFormMapper` |
| 限流器 | `service/OcrRequestLimiter.java` | `service/OcrRequestLimiter` |
| 响应 DTO | `ocr/OcrScanResponse.java` / `ocr/Ocr*Exception.java` | 同 |
| 接口入口 | `controller/OcrController.java` | `controller/OcrController` |
| 前端 | `frontend/src/core/views/ScanFillDialog.vue` | 同 |

**阿里云实现要点**(`AliyunOcrGateway`):`recognizeAllText` Advanced,`outputTable=true, outputRow=true`;
凭据 `yinjia.ocr.access-key-id/secret`(未配置 → 「OCR 服务未配置，请联系管理员」);
超时 connect 5s / read 30s 可配;响应 code 非空即报;日志脱敏 `redact`(AK 替换 `***`,>1000 字符截断)。

**限流**(`OcrRequestLimiter`):**用户 60s 滑动窗口**(默认 `yinjia.ocr.requests-per-minute=10`,
窗口满 → 「扫描过于频繁」)+ **全局并发信号量**(公平 `Semaphore(max-concurrent 默认 4)`,`tryAcquire`
失败 → 「OCR 服务正忙」);`Permit implements AutoCloseable` 与业务 `try-with-resources` 配对释放;
空闲用户窗口每 128 次申请清理一次(`evictIdleWindows`)。

**准入校验**(`OcrScanService.scan` 顺序):
1. panelCode 非空;2. `requirePanelAccess`:登录用户存在 `yj_user`(light-mes 走面板权限);
3. `requireEditableDocument`:面板 `metadata.panelCategory` 以「单据」结尾 且非 `readonly/readOnly`;
4. `validateImage`:非空、≤10MB、格式 ∈ {jpeg,jpg,png,bmp,gif,tif,tiff}(按 ImageIO 真实解码校验,
   防改扩展名)、宽高 ∈ (15, 8192)、长宽比 < 50、`setSourceSubsampling` 抽稀解码(防大图内存炸弹)。

**数据驱动字段映射**(`OcrFormMapper.map`,输入=面板 config + OcrDocument):
- 字段来源:`dataSchema.fields`(表头)+ `detail.tabs[]`(明细页签),嵌套字段递归展开;
- 排除:`SYSTEM_FIELDS` 28 个审计/状态键(编号/单据状态/审核人…)+ `hidden/computed/autoCode/readonly`
  + `metadata.autoCodeField/panelState`;
- 别名:`dataName` + `displayName/label/name` + 字段级 **`ocrAliases`**(数组,票据专属叫法,最高灵活度);
  `normalizeLabel` 去空格冒号再比对;多字段共享别名时按「先到先得」防串值;
- 表头匹配:`标签[:：]值` → `标签 空格 值` → `独立标签行 + 下一非标签行`(下一行是已知标签则跳过);
  字段按最长标签优先匹配;
- 明细表格:`bestTableMatch` 找「表头行」(该行单元格与字段别名命中数最多)→ 按 `rowStart/rowEnd/
  columnStart/columnEnd` 坐标取值;无表 → warning「未识别到可映射的明细表格」;
- 类型归一:`NUMBER(整数/小数/金额,剥 ￥¥RMB/元/件/kg/吨 等后缀,`[-+]?\d[\d,，]*(\.\d+)?`)`,
  `CHINESE_DATE(2026年1月2日)`/`SEPARATED_DATE(2026-01-02 / 2026/1/2)`,
  `BOOLEAN(是/√/1/true ↔ 否/×/0/false)`,选项 `options` 归一;非法值 → 跳过并写 warning。

### 复现要点

1. 三层职责切死:网关(调云 API+脱敏)、编排(准入+限流+gateway+map)、映射(纯函数,单测友好);
2. 限流双维度(按用户窗口 + 全局并发),缺一都会有「单用户刷爆」或「全站被一个慢请求拖垮」;
3. 图片校验要用**真实解码**(ImageIO reader)而不是只看扩展名;4. 字段映射必须「配置驱动 + 别名可配」,
   否则每换一种票据样式就改代码;5. 识别结果永远给用户人工确认通道(matches/warnings),不要静默回填。

## 2. 机器翻译(与 OCR 同凭据)

### 契约

`TranslationService.translate(locale, sources) → {中文原文: 译名}`,链路:
翻译表命中 → 直接返回;miss → **10 并发机翻**(`mt-translate` 固定线程池,全部完成后统一落库,
避免长词条串行阻塞切换)→ MERGE 写回 `yj_translation(source='mt')` → 返回;机翻失败或未配置凭据
**返回空串**(前端回退原文);`byLocale` 30s per-locale 缓存,`translate` 末尾 `invalidate` 该 locale。

- **凭据与 OCR 共用**:`${yinjia.ocr.access-key-id/secret}`(`application.yml`
  `ALIBABA_CLOUD_ACCESS_KEY_ID/SECRET` 语义);机翻 endpoint 由 OCR endpoint 推导:
  `mt.<region>.aliyuncs.com`(regionOf 从 endpoint 提取 `cn-xx/ap-xx/...` 段,缺省 cn-hangzhou)。
- 调用:阿里云 alimt `TranslateGeneral`,`scene=general`,`zh → aliLang(locale)`,`formatType=text`。
- 落库注意:`MERGE yj_translation` 的派生表参数必须显式 `CAST(? AS nvarchar(...))`,
  否则驱动按 varchar 发送,泰文/俄文等非拉丁字符变 `?`(UTF-8 编码污染,项目有 `repair-db-question-marks` 工具)。

### 关键文件路径

- YINJIA:`service/TranslationService.java`(L53-63 同凭据注入、L101-135 translate、L161-193 machineTranslate/mtClient);
  前端 `src/i18n/index.js` + `src/stores/locale.js`(registerDictFetcher/recordMiss/flushPending/dictVersion)。
- light-mes:`i18n/TranslationService.java`(同构);与 OCR 同凭据同理(00 盘点 C7)。

### 复现要点

1. MT 与 OCR 共用 AK 是约定,配置项名统一 `xxx.access-key-id`,一个环境变量喂两个服务;
2. 机翻只兜底显示层零星词条,结果必须落库成 `source='mt'`,人工校对可升级 `manual`;
   业务事实数据(**数据键/客户名/单据号不译**,ADR-0001);3. 并行池固定小并发(10)不追 QPS;
4. 失败静默,调用方永远拿到原文字符串兜底。

## 3. 通知 / 待办 / 预警(审批中驱动)

### 契约

`PortalNotificationService.badge(userName) → {todo, message, alarm}`(数量,顶栏角标)与
`list(userName, type) → items[]`;接口 `GET /api/portal/badge`、`GET /api/portal/notice/list`
(`PortalController`);item 结构 `{id, type, title, time, read, content, panelCode, formNo, targetPath,
actionLabel}`,`targetPath = /panelx/list/{panelCode}` 前端直达。

- **todo(待办)= 审批中单据驱动**:`yj_doc_status` 中 `pending='Y' AND canceled<>'Y'` 的 TOP 100,
  标题 `面板名 + 单号 + 待审批`,内容带「提交人 x 已提交…等待当前账号审批」;
- **message(消息)= 系统操作日志**:`s_log` 最近记录(USERID/MODULENA/GN/REMARK/COMM);
- **alarm(预警)= 低库存**:`kucun` 表 `asp_cancel<>'Y' AND yl < LOW_STOCK_THRESHOLD(=100,
  BigDecimal 常量)`,按 yl 升序,提供 warehouse/inventoryCode/quantity/threshold。

light-mes 同类三分类结构(数据源为 form_data + 操作日志表),YINJIA 仅换了数据源。

### 关键文件路径

- YINJIA:`service/PortalNotificationService.java`、`controller/PortalController.java`。
- light-mes:`service/PortalNotificationService.java`(同构)。

### 复现要点

1. 待办来源就是状态机的 `pending` 标志——**状态机是待办的唯一事实源**,别再造一张待办表;
2. 分类语义固定(todo/message/alarm),数量与列表同一数据源,别算两套;
3. item 必须带 `panelCode/formNo/targetPath/actionLabel` 供前端跳转与展示;
4. 阈值做成常量而非散落 SQL;消息类数据读取无状态,可直接 404/降级。

## 4. 报表服务(列设置 / 别名 / 合计)

### 契约

- **列设置**(YINJIA `ReportColumnSettingsService`):`report_column_settings` 按面板编码存 JSON
  `{columns:[{prop,label,visible}], sort:{prop,order}}`,**全部用户共享**;
  `GET/POST /api/px/reportColumnSettings`;load 无记录/JSON 损坏返回空 Map(不抛错),save 为
  UPDATE 无行则 INSERT(按面板编码 upsert)。
- **报表查询/聚合**(light-mes `ReportQueryService`):报表面板走 `ReportPanelRegistry`,查询时列
  按别名取值(`aliasValues`:同一字段可能有多个中文键,如「金额|实收金额」)、目标列做行级聚合
  累加(累计执行数量/费用合计/工资合计等)。
- 另一条列设置线(单据列表,差异见 00 盘点 B1a):YINJIA `saveColumnPrefs` 直接 UPDATE `yj_field`
  元数据(seq/alias/visible,全局生效);light-mes 独立表 `px_column_pref(panel_code, owner,
  col_name, seq, alias, visible)` 按 owner 用户级 + `applyColumnPrefs` 过滤排序追加新列。

### 关键文件路径

- YINJIA:`service/ReportColumnSettingsService.java`、`controller/PxController.java`(L79-93);
- light-mes:`service/ReportQueryService.java`、`panel/ReportPanelRegistry.java`、`PxService.saveColumnPrefs`
  (L721)+ `px_column_pref` 表。

### 复现要点

1. 列设置结构与 UI 列模型解耦(prop/label/visible 三元组足够);2. 损坏 JSON 必须降级为空设置
   而非 500;3. 别名表(字段英文键 ↔ 显示中文键)是报表复用的前提——多语言下中文键正好是显示键,
   别名机制让「一个逻辑列多个叫法」可查询可展示;4. 合计/累计放查询层聚合而不是前端累加,
   保证分页正确。

## 5. 导入导出

### 契约

- **导入**(两项目同构,前端为主):`core/views/ImportDialog.vue` —— Excel 模板下载 / 预览 /
  字段映射 / 校验,后端无专有导入服务,数据经 px 契约(列表/表单接口)提交。
- **导出**(前端引擎,两项目同构):`core/views/PanelxList.vue` —— **报表 = 整表 CSV;
  单据 = 当前明细页签 CSV**(含 BOM/别名,「PANDA 打印组·导出」);导出/打印按钮可用性由
  `getPermMatrix` 的 `export/print` 权限码控制。

### 关键文件路径

- YINJIA:`frontend/src/core/views/ImportDialog.vue`、`frontend/src/core/views/PanelxList.vue`
  (L2148-2172 明细导出、L2416-2417 报表导出分支);接口 `POST /api/px/queryFormDataList`。
- light-mes:`frontend/src/core/views/ImportDialog.vue`、列表引擎(同构)。

### 复现要点

1. 导入导出放在「面板引擎」层而非各面板,任何面板自动具备(B7/B8);2. 导出带 `\ufeff` BOM 头
   (Excel 打开 CSV 中文不乱码)、列名用字段别名;3. 导入必须「模板+预览+映射」三步,防止
   用户拿错列;4. 导入写库走与手工保存相同的校验入口(状态/必填/软删约定),不要旁路。

## 6. 验收锚点

1. 上传 10MB+ 图片 → body-code 400「图片不能超过10MB」;连续 11 次扫描 → 429「扫描过于频繁」;
2. 未配置 AK 扫描 → 503「OCR 服务未配置」(不崩、前端不登出);
3. 一张含「客户:张三」与金额 ¥1,234.50 的表单图 → table 页回填 `客户=张三`、金额 `1234.50`(数字归一),
  表头外字段出现在 matches 供核对;4. 切换 en 时缺失词条自动机翻并落库(`yj_translation source='mt'`),
  再次切换不再请求;5. 提交一张审批中单据 → 门户 todo 角标 +1,点击直达该面板列表;
6. 报表改列显隐/别名 → 刷新后保持;7. 列表导出 CSV 用 Excel 打开中文正常、列名=别名。
